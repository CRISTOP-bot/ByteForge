# ByteForge training corpus — Spanish systems programming and OS development.
Un sistema operativo administra procesos memoria dispositivos archivos permisos y llamadas al sistema.
El kernel inicia el sistema configura interrupciones prepara memoria física y virtual y entrega el control al planificador.
El kernel debe validar cada puntero de usuario antes de copiar datos a memoria del núcleo.
Una llamada al sistema cambia de modo usuario a modo kernel mediante una instrucción controlada por la arquitectura.
La tabla de páginas traduce direcciones virtuales en direcciones físicas y define permisos de lectura escritura y ejecución.
El asignador físico administra marcos de páginas; el asignador virtual administra regiones y espacios de direcciones.
No escribas en una dirección física sin mapearla correctamente en el espacio virtual del kernel.
El planificador guarda el contexto del proceso saliente y restaura el contexto del siguiente proceso ejecutable.
Un cambio de contexto debe preservar registros la pila y el estado necesario para reanudar la tarea.
Las interrupciones deben reconocer el dispositivo y enviar el fin de interrupción al controlador adecuado.
Los controladores de dispositivo deben validar registros y manejar errores reales, no simular éxito.
Un sistema de archivos debe comprobar límites, permisos y errores de entrada y salida.
El cargador ELF valida cabeceras segmentos tamaños y direcciones antes de mapear un ejecutable.
Un bootloader entrega al kernel un mapa de memoria y los argumentos de arranque definidos por el protocolo.
Para depurar un kernel usa símbolos de depuración registros seriales y una máquina virtual reproducible.
Una prueba unitaria del host no demuestra que el kernel arranque en QEMU ni que funcione en hardware.
En C, libera cada recurso exactamente una vez y comprueba el resultado de cada asignación de memoria.
En C, un puntero nulo no se puede desreferenciar y un acceso fuera de límites causa comportamiento indefinido.
Los enteros sin signo pueden desbordarse; valida tamaño y longitud antes de calcular offsets.
Usa tipos de tamaño fijo para estructuras binarias y documenta el endianess del formato.
Comprueba el valor de retorno de read y write; pueden completar menos bytes de los solicitados.
En Rust, la propiedad y los préstamos ayudan a expresar quién puede modificar cada región de memoria.
El código unsafe debe ser pequeño, documentado y respaldado por invariantes verificables.
En Go, goroutines y canales facilitan servicios concurrentes pero no reemplazan el manejo de errores.
En Java, el recolector de basura no administra recursos nativos como descriptores y memoria mapeada.
Python sirve para automatizar builds analizar logs y generar imágenes de disco reproducibles.
Un Makefile debe fallar si una herramienta falta y nunca sustituir una toolchain cruzada por el compilador del host.
Fija versiones de dependencias verifica licencias y registra los comandos exactos de compilación.
El compilador cruzado x86_64-elf genera binarios bare metal sin enlazar accidentalmente la libc del host.
El linker script define direcciones de carga secciones símbolos y alineación del kernel.
Una compilación exitosa no prueba que el sistema operativo sea funcional.
Los tests deben comprobar resultados observables y cubrir límites errores y rutas de fallo.
El arranque de BIOS y UEFI requiere pruebas distintas; no afirmes soporte sin iniciar la imagen.
Un sistema seguro aplica mínimo privilegio valida entradas y evita ejecutar páginas de datos.
La memoria compartida requiere sincronización explícita para prevenir condiciones de carrera.
Los bloqueos deben tener reglas de orden para evitar interbloqueos.
El registro serial permite inspeccionar el arranque temprano cuando todavía no hay consola gráfica.
Para una regresión agrega primero un caso de prueba que reproduzca el fallo y luego corrige su causa.
La documentación distingue lo implementado, lo experimental y lo planeado.
No declares un driver funcional si solo contiene estructuras vacías o valores simulados.
Un kernel pequeño puede enseñar arranque, memoria, interrupciones, procesos y sistemas de archivos con experimentos reales.
ByteForge aprende patrones de código y texto técnico; no compila programas ni verifica que el código generado sea correcto.
El modelo es educativo y limitado: genera secuencias probabilísticas, no entiende el significado como una persona.
Para experimentar añade ejemplos con licencia clara y revisa el corpus antes de entrenar.
La reproducibilidad requiere fijar corpus semilla versión de herramientas y parámetros de entrenamiento.
Un buen informe de pruebas especifica el commit exacto, los comandos ejecutados y los resultados observados.
La seguridad del kernel depende de contratos claros entre arquitectura memoria procesos y controladores.
La arquitectura x86-64 define registros instrucciones excepciones y convenciones de llamada.
En ensamblador x86-64 preserva los registros callee-saved y respeta la alineación de la pila antes de llamar funciones.
Una rutina NASM recibe argumentos conforme a la ABI System V y devuelve el índice elegido en RAX.
El firmware y el kernel se comunican mediante estructuras cuya versión y tamaño deben verificarse.
El código de arranque temprano evita depender de memoria dinámica antes de inicializar el asignador.
Los mensajes de error deben identificar el subsistema y conservar suficiente contexto para depurar.
En C, una función debe comprobar los errores de lectura y escritura antes de continuar.
En C, size_t representa tamaños y longitudes; valida que una suma no se desborde antes de reservar memoria.
En C, copia los datos del usuario a un búfer del kernel validado antes de procesar una llamada al sistema.
En C, enumera explícitamente los estados de un proceso para que las transiciones sean auditables.
En C, una función de asignación devuelve NULL cuando no puede reservar memoria; el llamador debe manejarlo.
En C, usa const cuando la función no debe modificar el búfer recibido.
En C, revisa el tamaño de una estructura antes de leerla desde un archivo binario.
En C, no uses una variable después de liberar el objeto al que apunta.
En C, comprueba que el índice sea menor que la cantidad de entradas de la tabla.
En ensamblador x86-64, una rutina de interrupción conserva el estado requerido antes de llamar a código C.
En ensamblador x86-64, la instrucción ret usa la dirección de retorno en la pila.
En ensamblador x86-64, el ABI System V pasa los primeros argumentos enteros en RDI RSI RDX RCX R8 y R9.
En ensamblador x86-64, antes de call alinea la pila según la ABI de la plataforma.
Un linker script puede ubicar .text .rodata .data y .bss en las regiones de memoria definidas para el kernel.
El símbolo _start identifica una entrada de bajo nivel solo si el linker script y el cargador acuerdan ese contrato.
Un Makefile declara dependencias explícitas para recompilar solo los objetos que cambiaron.
El objetivo clean elimina únicamente los artefactos generados del proyecto.
Una toolchain cruzada evita enlazar inadvertidamente bibliotecas del sistema anfitrión en un kernel bare metal.
El comando readelf -h permite inspeccionar el tipo y la arquitectura declarados en una cabecera ELF.
El comando objdump -d muestra instrucciones desensambladas para revisar código máquina generado.
QEMU puede arrancar kernels de prueba y registrar la salida serial para automatizar verificaciones.
Un test de arranque comprueba marcadores observables y un tiempo máximo, y falla ante un kernel que se bloquea.
Una prueba de memoria debe cubrir asignación, liberación, alineación, agotamiento y límites de direcciones.
Una prueba de syscall verifica número de llamada, argumentos válidos, argumentos inválidos y códigos de error.
Al revisar una contribución comprueba la rama base el commit exacto los archivos afectados y las pruebas ejecutadas.
La documentación técnica no debe afirmar soporte de teclado USB si no existe un driver integrado y probado.
Un ejemplo de configuración debe usar opciones reales del programa y fallar claramente cuando falta una dependencia.
Los mensajes del bootloader no sustituyen las pruebas de inicialización de memoria y planificación del kernel.
El entrenamiento de ByteForge tokeniza texto y cuenta continuaciones locales; no ejecuta ni compila el texto del corpus.
